# Checkout & Fulfillment Setup Guide

هذا الدليل يوضح كيفية تهيئة رحلة شراء متكاملة (إضافة للسلة ➜ الدفع ➜ الشحن) في مشروع **my-store** سواء لبيئة التطوير أو التحضير للإطلاق.

## 1. المتطلبات الأساسية
- Node.js 18 أو أحدث.
- MySQL 8 (محلياً أو من خلال خدمة مستضافة مثل Railway).
- حسابات لمزودي الدفع المراد تفعيلهم (PayPal, Stripe, STC Pay، أو بيانات تحويل بنكي).
- مفاتيح خرائط اختيارية إذا رغبت بتخصيص تجربة تحديد الموقع، لكن التطبيق يعمل بدونها.

## 2. ضبط قاعدة البيانات
1. حدّد سلسلة الاتصال `DATABASE_URL` في ملف `.env` الجذري (صيغة MySQL).
2. شغّل التوليد والمزامنة:
   ```bash
   npm run db:generate
   npm run db:push
   npm run db:seed   # اختياري لإنشاء بيانات تجريبية (منتجات، مستخدم إداري)
   ```
3. إذا أردت الاتصال بقاعدة بيانات سريعة للتجربة يمكنك استخدام الوضع المجلوب مسبقاً:
   ```bash
   cross-env QUICK_START_DB=1 ALLOW_INVALID_DB=true npm run dev:server
   ```
   > يعطي الخادم سلسلة اتصال Railway اختبارية ويعمل في وضع مخفّف بدون عمليات كتابة حقيقية.

## 3. المتغيرات البيئية الرئيسية
ضع هذه المتغيرات في `.env` الخاص بالخادم (`server/.env.local` أو الجذر) حسب مزود الدفع الذي ستفعّله.

### 3.1 المصادقة والدخول
| Variable | القيمة | الغرض |
|----------|--------|-------|
| `JWT_SECRET` | مفتاح عشوائي قوي | لتوقيع الرموز.
| `ALLOW_DEV_HEADERS` | `true` في التطوير | يسمح بتجاوز تسجيل الدخول عبر الترويسة `x-user-id`.

### 3.2 بوابات الدفع
| الطريقة | متغيرات مطلوبة |
|---------|----------------|
| **PayPal** | `PAYPAL_CLIENT_ID`, `PAYPAL_SECRET`, `PAYPAL_API` (عادة `https://api-m.sandbox.paypal.com` للتجارب), `PAYPAL_RETURN_URL`, `PAYPAL_CANCEL_URL`, `PAYPAL_WEBHOOK_ID` (اختياري لكن يوصى به). |
| **Stripe** | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`. تاكد من إضافة عنوان الـ webhook عبر لوحة Stripe إلى `/api/pay/stripe/webhook`. |
| **STC Pay** | `STC_API_BASE` (إن لزم)، `STC_MERCHANT_ID`, `STC_API_KEY`, `STC_API_SECRET`. قم بتمكين الحقل `payStcEnabled` من إعدادات المتجر أو عبر لوحة الإدارة. |
| **تحويل بنكي** | `BANK_ACCOUNT_NAME`, `BANK_ACCOUNT_IBAN`, `BANK_NAME` لتظهر للعميل أثناء التحويل. |
| **الدفع عند الاستلام** | فعل العلم `payCodEnabled` في إعدادات المتجر (تمكين افتراضي). |

### 3.3 إعدادات الشحن
| Variable | القيمة | الوصف |
|----------|--------|-------|
| `STORE_ORIGIN_LAT`, `STORE_ORIGIN_LNG` | إحداثيات المستودع أو نقطة الانطلاق | تستخدم لحساب المسافة بنموذج Haversine. |
| `SHIPPING_BASE` | قيمة ابتدائية (افتراضياً 10) | رسم ثابت يبدأ منه الحساب. |
| `SHIPPING_PER_KM` | تكلفة الكيلومتر (افتراضياً 0.7) |
| `SHIPPING_MIN`, `SHIPPING_MAX` | أقل وأعلى قيمة ممكنة للرسم |
| `SHIPPING_FALLBACK` | قيمة ثابتة تستخدم عند عدم تعرّف المدينة |

> يمكن تعديل نفس القيم لحالة اختبارية عبر استدعاء `/api/shipping/quote` وتمرير إعدادات مختلفة في جسم الطلب.

## 4. تشغيل البيئة المحلية
```bash
# تثبيت الحزم
npm install

# تشغيل الخادم (Express + Prisma)
npm run dev:server

# تشغيل الواجهة (Vite)
npm run dev -w client
```
- سيعمل الخادم على منفذ 8829 (ويتحول تلقائياً إن كان مشغولاً).
- الواجهة على 5173 وتقوم بالوكالة لجميع طلبات `/api` إلى الخادم.

## 5. رحلة الشراء (تجربة عملية)
1. **تسجيل الدخول**: أنشئ حساباً أو استخدم مستخدم الإدارة الذي تم زرعه (راجع `db/seed`). في التطوير يمكن إرسال ترويسة `x-user-id` عندما يكون `ALLOW_DEV_HEADERS=true`.
2. **إضافة المنتج**:
   - انتقل إلى `/products` أو صفحة المنتج (`/products/:id`).
   - استخدم زر "أضف للسلة"؛ سيتم تحديث السياق `CartContext` وإطلاق نوتي في الرأس.
3. **استعراض السلة** (`/checkout/cart` أو أيقونة السلة):
   - تأكد من أن الأزرار (زيادة/إنقاص/إزالة) تعمل وتنعكس القيم فوراً.
4. **الانتقال للدفع** (`/checkout`):
   - أدخل العنوان (الحقل GPS اختياري).
   - سيقوم النظام بمناداة `/api/shipping/quote` واعتماد الرسوم المحسوبة.
   - اختر وسيلة الدفع المتاحة.
5. **إنشاء الطلب**:
   - الزر "مراجعة الطلب" ينشئ سجل الطلب عبر `/api/orders` ويعيد استخدامه إن عُدِّل المحتوى.
   - في خطوة المراجعة يمكن تعديل الكميات أو حذف منتج؛ يتم تحديث الإجماليات مباشرة.
6. **معالجة الدفع**:
   - **PayPal**: سيتم إنشاء `create-order` ثم فتح `PayPalButtons` لإتمام العملية. بعد الموافقة يتم استدعاء `/pay/paypal/capture` وتعيين حالة الطلب إلى `paid`.
   - **Stripe**: يستدعي `/pay/stripe/create-intent` ليحصل على `clientSecret` ثم يتم تأكيد الدفع من خلال `CardElement`.
   - **STC Pay**: يولد جلسة عبر `/pay/stc/create` مع مسار محاكاة للتأكيد.
   - **تحويل بنكي**: `/pay/bank/init` يعرض الـ IBAN والمرجع؛ يمكن رفع وصل الدفع عبر `/pay/bank/upload` ومراجعته من لوحة الإدارة.
   - **الدفع عند الاستلام**: يعتمد على الحالة الافتراضية للطلب دون تفاعل مع مزود خارجي.
7. **الشحن**:
   - بعد الدفع، استخدم `/api/orders/:id/ship` لاختيار مزود (Aramex أو SMSA) عندما تكون المفاتيح مهيأة في `StoreSetting`.
   - يمكن متابعة حالة الشحنة عبر `/api/orders/:id/ship?refresh=1`، أو استقبال بثّ SSE من `GET /api/events`.

## 6. نقاط تكامل إضافية
- **الإشعارات**: يتم إرسال إشعار حالة الطلب من خلال `sendOrderStatusNotification`؛ تأكد من إعداد قنوات البريد/SMS وإن كانت غير مطلوبة يمكن تركها معطلة.
- **الفواتير**: بعد الترقية إلى حالة `paid` يتم إنشاء فاتورة PDF (بحاجة Puppeteer). إذا كانت بيئة الإنتاج لا تدعم Chromium؛ عيّن `PUPPETEER_SKIP_DOWNLOAD=1` وسيعيد الخادم كود 501 بدلاً من التعطل.
- **الواجهة الإدارية**: لإدارة البانرات ورسائل القيمة تأكد من نشر التغييرات الأخيرة في `MarketingView.jsx` واستخدام حساب إداري.
